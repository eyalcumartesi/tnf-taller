lo que NO es mito: la randomness

  • un LLM predice el próximo token
  • cada predicción es una probabilidad
  • siempre habrá randomness — no es un bug, es la naturaleza de la herramienta

por eso todo lo que viene hoy existe: estructura alrededor de algo probabilístico.

orquestar agentes: la escalera

~20 min
~ escucha

worktrees: agentes en paralelo sin pisarse

  • mismo repo, directorios separados, branches separados
  • cada agente en su sandbox — cero conflictos, cero contaminación de contexto
  • yo los uso todos los días. va en tu global config (se los entrego)
  • techo real 2026: 4–8 agentes por dev. arriba de eso, el cuello es TU review
~ escucha

el ralph loop: código mientras duermes

while :; do
  cat PROMPT.md | claude -p
done
  • el agente corre en loop hasta cumplir un criterio de "done" (tests, tags)
  • el progreso vive en archivos y git, no en el contexto
  • resultados reales: Huntley, 3 meses de loop → un lenguaje de programación completo. hackathon de YC → 6+ repos overnight por $297

no arranques overnight: primero iteraciones manuales, algo low-stakes, y vigila el costo.

lo que vas a usar de git

commit    → guardar un cambio con nombre

push      → subirlo a GitHub
