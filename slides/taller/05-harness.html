capa 1/4 · gobierno — el borde ámbar del diagrama

config: las reglas del harness

no son comandos ni tools — es cómo se comporta el agente antes de tocar nada.

🌐
global · una vez
el stack que no vas a redefinir cada vez: Next.js, shadcn, Supabase, pnpm, Drizzle. lo arma el agente desde el ejemplo, al inicio.
📁
proyecto · ya en el repo
qué es la app y cómo se corre. viene definido, no lo escribes: lo abres y listo.

para founders no-técnicos: el global carga el peso, el proyecto queda finito. no lo memorizan, lo heredan.

capa 2/4 · tooling — la caja cian del diagrama

skill · command · subagente · MCP: ¿cuál?

la regla es por forma, no por tamaño:

primitivo✓ úsalo para✗ no para
/commandun prompt que repites una sola instrucción: correr tests, formatear si necesita pasos o archivos → es un skill
skillworkflow multi-paso, auto-carga armar un PR · convenciones del repo · "cómo se corre esto" algo que Claude ya hace bien · docs que cambian seguido
subagentecontexto fresco, en paralelo explorar codebase · research · criticar el diff si no necesita contexto fresco, pagas aislamiento de más
MCPsistema externo, vivo GitHub · base de datos · Playwright solo leer/mostrar → usa web search

en el demo armamos un skill: crear-pr — lo que hacías a mano, empaquetado una vez.

capa 3 → 4 · el agente (ya lo viste) y su loop LLMOps

el cierre: critique pattern

nunca aceptes el primer output · un subagente fresco critica sin el sesgo de quien lo escribió.

4
solo ahí revisas túllegas a algo ya pulido
3
se corrige con la críticael output se rehace con el feedback
2
un subagente criticave solo el diff y los criterios · nativo: /code-review
1
el agente construyeproduce el primer intento
ataca directo la randomness. es el pattern con mejor retorno por esfuerzo.
